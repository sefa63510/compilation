INTRODUCTION
--------------------------------------------------
Définition : compiler, c'est traduire un programme écrit dans un
langage source L vers un langage cible L'.

Objectif : comprendre les principaux concepts d'un compilateur.
On se restreint à :
  - certaines constructions des langages de programmation
    (pas de constructions dynamiques)
  - certaines étapes de la compilation

Étapes étudiées :
  1. Analyse lexicale      (principes)
  2. Analyse syntaxique
  3. Analyse sémantique
  4. Génération de code

Pratique :
  - Chaque étudiant conçoit son propre langage, avec des
    constructions imposées.
  - Langage cible L' : langage d'une machine virtuelle, la MVaP.
  - Outil de génération du compilateur : ANTLR4.
  - Langages d'écriture : le langage d'ANTLR et Java.

Évaluation (MCCC) :
  - Examen écrit (décembre ou janvier)
  - TP noté

À retenir :
  - La syntaxe du langage à concevoir est décrite par une
    grammaire hors contexte.
  - Certaines constructions sont ambiguës : on verra des
    heuristiques pour les rendre non ambiguës.


==================================================
CHAPITRE 1 : ANALYSE LEXICALE
==================================================

Schéma :

  Code source --(flux de caractères)--> Analyseur lexical
              --(jetons)--> Analyseur syntaxique

Définitions :
  - Jeton : ensemble d'informations qui caractérise un objet
    considéré comme un terminal de la grammaire hors contexte.
  - Lexème : suite de caractères du code source.
  - Unité lexicale : ensemble (classe) de lexèmes de même nature.


EXEMPLE 1
--------------------------------------------------
Grammaire : E -> E + E | E * E | nb
Code source : nb + nb + nb * nb * nb + nb

Lexèmes : 11 au total
  - 6 occurrences de nb
  - 3 occurrences de +
  - 2 occurrences de *

Unités lexicales : 2
  - une pour le lexème nb
  - une pour les lexèmes + et *
(Si on crée une unité par terminal : 3 unités, nb, + et *.)


EXEMPLE 2 : GRAMMAIRE AMBIGUË
--------------------------------------------------
Grammaire :
  F -> F * F | F + F | I
  I -> 0 I | 1 I | epsilon

Mot analysé : 0 + 1 * 01 * 110 + 111

Arbre de dérivation (début) :

                 F
           +-----+-----+
           F     +     F
           |           |
           I        +--+--+
           |        F  *  F
           0        |     |
                    I     ...

Ce mot admet plusieurs arbres de dérivation, car + et * ont la
même priorité et aucune associativité n'est imposée.
La grammaire est donc ambiguë.


Un jeton est composé :
  - d'une unité lexicale T
  - d'un lexème de T
  - d'autres informations :
      - numéro de ligne, numéro de colonne
      - valeur (ex : la valeur entière pour un lexème qui
        représente un entier)

L'analyseur lexical produit un flux de jetons pour l'analyseur
syntaxique.


COMMENT FAIRE ?
--------------------------------------------------
  - Chaque unité lexicale du langage est décrite par une
    expression régulière.
  - Un analyseur lexical = l'union des automates à états finis
    associés aux unités lexicales
    + des actions qui calculent les jetons à partir des lexèmes
      reconnus.


LES DEUX PROBLÈMES À RÉSOUDRE
--------------------------------------------------
  1. Intersection de deux unités lexicales :
     laquelle choisir pour un lexème lu ?
  2. Un lexème peut être préfixe d'un autre lexème :
     que faire ?


A/ CAS DE L'INTERSECTION DES UNITÉS LEXICALES
--------------------------------------------------
Solution simple : on ordonne les règles des unités lexicales.
Quand un lexème appartient à plusieurs unités lexicales, on choisit
celle dont la règle est écrite en premier.

Avec ANTLR : l'ordre retenu est l'ordre d'écriture des règles.

Exemple :
    BEGIN : 'begin' ;
    ID    : [a-z]+ ;

Il y a 2 unités lexicales, BEGIN et ID. Le lexème "begin"
appartient aux deux : il sera considéré comme un lexème de BEGIN,
car cette règle est écrite avant ID.


B) CAS D'UN LEXÈME PRÉFIXE D'UN AUTRE
--------------------------------------------------
Deux solutions :

  - Greedy (gourmand) : on lit le lexème le plus long possible.
    C'est la solution par défaut d'ANTLR.

  - Non greedy : on prend le lexème le plus court. Dès qu'une
    suite de caractères est acceptée, on arrête la lecture.
    (En ANTLR, on l'écrit avec l'opérateur ?, par exemple .*? )

Exemple : Beginner avec la méthode glouton sera reconnus comme 1 lexème de ID 
          Avec la méthode non glouton , il y'aura deux lexème 
          'begin' et 'non'

Exemple 2 : STRING : ' " ' . * ' " ' 
Avec la méthode gloutonne  : " m1 " " m2 "
